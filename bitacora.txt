## Uso de elementos semánticos
Los contenedores `div` que agrupaban la etiqueta y su control fueron reemplazados por `label`, que asocia cada campo con su nombre. El `div` usado como envoltorio del formulario de reservas se reemplazó por una `section` identificada por el título "Reserva tu bicicleta". Los `span` que indicaban que un campo era opcional se reemplazaron por `small`, apropiado para texto secundario.

## Formulario de reserva
El correo usa `type="email"` para validar una dirección con formato de correo; el tipo de bicicleta usa un `select` porque se elige una opción de una lista cerrada; la duración usa botones `radio` porque las opciones son mutuamente excluyentes. La confirmación usa una casilla obligatoria para registrar la aceptación explícita, y los detalles adicionales se recogen con un área de texto para permitir respuestas libres.

## MiniReto de diseño responsive

Se reorganizó `style_prueba.css` con estilos base móviles y media queries `min-width` en 768 px (tablet) y 1200 px (escritorio). Se conservó el viewport existente y se ajustó el diseño de portada, galería de rutas, navegación, pie de página y reservas.

### Problemas encontrados y solución

1. **La navegación se desbordaba en celulares:** los enlaces tenían un ancho fijo y la lista usaba espacios de 150 px. Se cambió el encabezado móvil a columna, con el nombre centrado arriba y los enlaces centrados debajo; desde 768 px vuelve a la fila horizontal.
2. **La portada y las imágenes de rutas no se adaptaban:** la portada y la galería forzaban varias columnas, y algunas imágenes usaban altura de 100 %. Se dejó una columna como base, se agregaron rejillas de dos y tres columnas según el ancho, y se limitaron las imágenes al contenedor con proporción y recorte controlados en las tarjetas.
3. **Las tablas de tarifas ocupaban más que la pantalla:** el relleno era amplio para tablas de cuatro y cinco columnas. Se fijó el ancho al contenedor, se redujeron tipografía y relleno en móvil y se permitió que el texto largo se ajuste dentro de las celdas; en tablet vuelve un tamaño mayor.
4. **El formulario de reservas tenía columnas incompatibles con móvil:** la definición `minmax()` de la rejilla era inválida y el horario estaba anidado en el formulario. Se corrigió la rejilla, se ordenó el marcado y se dejó el horario como columna lateral desde 1200 px, apilado en pantallas menores.

### Verificación responsive

Se comprobó la página de inicio, tarifas y reservas en Chromium con viewports de 360, 768, 1200 y 1280 px. No hubo desbordamiento horizontal; las imágenes y tablas quedaron dentro del ancho visible. La navegación cambió de columna a fila a partir de 768 px, la galería pasó de una a dos y luego tres columnas, y el horario de reservas pasó a columna lateral a partir de 1200 px.

## Comparación de la grilla propia con Bootstrap 5.3

- **Tiempo invertido:** aproximadamente 2 minutos en reconstruir y comprobar la página de prueba.
- **CSS de distribución de la flota en la versión propia:** 11 líneas en `style_prueba.css`: 5 para la grilla base de una columna, 3 para dos columnas desde 48 rem y 3 para tres columnas desde 75 rem.
- **Clases en esta versión Bootstrap:** cada una de las 7 tarjetas usa `col-12 col-sm-6 col-lg-4 col-xl-3` (4 clases por tarjeta; 28 usos en total). El contenedor añade `container`, `row` y el gutter `g-4`. No se añadió CSS propio ni se enlazó `styles.css`.
- **Qué dio Bootstrap sin esfuerzo:** puntos de quiebre estándar para una, dos, tres y cuatro columnas; separación consistente entre tarjetas; contenedor adaptable, estilos de tarjeta, tipografía y espaciado. El CSS y el bundle JavaScript se cargan desde el CDN oficial 5.3.8.
- **Qué control se pierde:** frente a las reglas propias, se reduce el control fino del diseño de tarjetas, colores, tipografía, separación y apariencia de imágenes; para cambiar esos detalles hay que elegir utilidades/componentes de Bootstrap o añadir CSS propio, lo que esta página de prueba evita deliberadamente.
- **Comprobación:** en modo dispositivo se verificaron 375, 576, 991, 992, 1199 y 1200 px; la flota mostró respectivamente 1, 2, 2, 3, 3 y 4 columnas. Las siete imágenes cargaron y no hubo solicitudes fallidas, respuestas HTTP de error ni errores de consola para CSS/JS del CDN.

## Utilidades Bootstrap para beneficios y reservas

Consulté la documentación oficial de Bootstrap 5.3 (utilidades de espaciado, display, flex y colores) para construir la sección de beneficios y la franja de reservas sin CSS propio:

- `col-md-6`: ocupa la mitad de la fila desde el breakpoint `md`; con `col-12`, cada beneficio ocupa todo el ancho en celular.
- `d-none d-md-block`: oculta el elemento decorativo en celular y lo muestra como bloque desde `md`.
- `flex-column flex-md-row`: apila el contenido en celular y lo dispone en fila desde `md`.
- `gap-4`: establece separación uniforme entre elementos del contenedor flex.
- `text-bg-dark`: aplica de forma conjunta fondo oscuro y texto claro, con el contraste definido por Bootstrap.

## Integración de Bootstrap en la página de inicio

Bootstrap 5.3.8 se carga antes de `style_prueba.css`, que es la hoja existente compartida por el sitio (no existe un archivo `styles.css`). La portada, servicios, flota, rutas y beneficios ahora usan `container`, `row`, columnas responsivas, gutters y utilidades. Se retiraron las reglas de distribución propias que Inicio dejó de usar; las reglas de tablas, tarifas y reservas permanecen señaladas en la hoja.

### Conflictos observados en DevTools y solución

1. **Ancho del contenedor:** la antigua regla `main { width; margin; }` ganaba a `.container` y reducía el ancho disponible. Se dejó `main` para el crecimiento flexible y se limitó el ancho propio a `main:not(.container)`, de modo que `.container` de Bootstrap controle Inicio.
2. **Tipografía, márgenes y color de encabezados:** los estilos globales `h1`–`h6` cambiaban el aspecto de los títulos de Bootstrap. Se conservaron Georgia y el azul noche de marca; `fs-*` define los tamaños, `mt-0`/`m-0` controla los márgenes de los encabezados de tarjetas y `.card-title, .card-header` mantiene el color de marca sin `!important`.
3. **Enlaces de Bootstrap frente a la identidad del sitio:** el selector global `a` aplica el verde de marca, texto blanco y estados naranja, en lugar del enlace azul subrayado de Bootstrap. Se mantuvo esa decisión visual en la hoja cargada después del CDN; `.cta-button` conserva explícitamente el estilo de llamada a la acción. DevTools confirmó los colores de marca en los enlaces y los valores responsivos de las utilidades Bootstrap.

**Verificación:** se comprobó Inicio en modo dispositivo a 360, 768 y 1280 px. La grilla muestra una columna en móvil, adapta flota y beneficios a dos columnas desde `sm`/`md`, y alcanza tres/cuatro columnas en escritorio según cada sección. No hubo desbordamiento horizontal ni solicitudes fallidas; las 19 imágenes cargaron y el CDN no reportó respuestas HTTP de error.

## Prototipo Tailwind: Rueda Nocturna

- En la semana 2, el botón de Bootstrap se construyó como `<a class="btn btn-primary btn-lg">Inscríbete</a>`: `btn`/`btn-primary` aportan el componente y `btn-lg` su tamaño; las variables `--bs-btn-*` dan los estados de marca.
- Hoy, el enlace se construye como `<a class="inline-flex rounded-full bg-amber-300 px-7 py-4 font-bold text-slate-950">Inscríbete</a>` y suma utilidades `hover`/`focus-visible`; Tailwind Play CDN genera los estilos sin CSS propio.
- Diferencia clave: Bootstrap ofrece componentes predefinidos que se personalizan; Tailwind es utility-first y permite construir el componente combinando clases de propósito único en el marcado.
- El prototipo incluye la campaña «Nuevo · Jueves a sábado», el título «Rueda Nocturna», su descripción, los datos de rutas y precio, y el enlace de inscripción; conserva un solo `h1` y se adapta a pantallas pequeñas.
- Se deja el trabajo local, sin commit ni push.

## CLI de Tailwind y botones de Rueda Nocturna

- En `nocturna/` se instaló `tailwindcss` junto con `@tailwindcss/cli`. `src/input.css` importa Tailwind y la compilación se ejecuta en modo observación con `npm run watch`; `index.html` carga el CSS generado localmente, sin Play CDN.
- `src/output.css` incluye utilidades encontradas en el HTML, por ejemplo `.bg-slate-950`, y no incluye `.bg-pink-500`, que no se usa en los archivos fuente. Tailwind detecta las clases presentes en las fuentes y solo genera las utilidades necesarias; por eso una clase no usada no aparece en el CSS final y el archivo compilado ocupa menos.
- Se añadieron variantes principal, secundaria y de contorno. Cada enlace tiene un cambio `hover:` y un anillo `focus:ring-*` con separación visible al navegar con teclado; el foco no queda sin indicador al retirar el outline predeterminado.
- `nocturna/.gitignore` excluye `node_modules/`; se incluye `src/output.css` en el repositorio para que GitHub Pages pueda servir la página sin ejecutar la CLI.

- **Acentos y estados:** esmeralda para la acción principal y éxito; ámbar para la acción secundaria, precio y advertencia; sky para información. Los botones tienen `hover:` y anillo `focus:` visible; los campos comparten borde, relleno y foco esmeralda.

- Antes de los ajustes, la navegación de secciones permanecía visible en el celular. El encabezado usaba una fila con `flex-wrap` y mandaba la navegación a otra línea; no cumplía el diseño móvil compacto con solo logo y botón de inscripción.
- El título principal medía 48 px y el espacio entre bloques era de 64 px (`gap-16`, además de 48 px de padding vertical), una escala amplia para la pantalla pequeña.
- No había scroll horizontal: las tres rutas y los cuatro pasos ya se apilaban en una columna, las imágenes cargaban y las cards cabían en el ancho disponible. El problema observado era principalmente el encabezado y la escala de espaciado/tipografía, no contenido roto o recortado.

Las imágenes de las tres rutas cargaron en los cuatro anchos. Se redujeron título, padding y separación en móvil y se aumentaron progresivamente con `sm:`, `md:` y `lg:`. La navegación del encabezado usa `hidden md:flex`; la cuadrícula de rutas usa base de una columna, `sm:grid-cols-2` y `lg:grid-cols-3`.

## Tema de marca y modo oscuro de Rueda Nocturna

- `nocturna/src/input.css` define con `@theme` Verde Ruta (`#1E7A4F`), Naranja Pedal (`#F39A2B`), Azul Noche (`#14213D`), Crema (`#FAF6EF`), Gris Asfalto (`#5B6470`) y Amarillo Farol (`#FFD166`), además de Montserrat y Open Sans. Ambas páginas cargan las fuentes desde Google Fonts; el navegador confirmó que las dos familias están disponibles.
- La landing y `componentes.html` usan las utilidades de color y tipografía generadas por el tema. El modo oscuro sigue la preferencia del sistema (`prefers-color-scheme`) y ajusta fondos, textos, cards, alertas, bordes y campos. `src/output.css` incluye los estilos compilados para GitHub Pages; no quedan utilidades de colores genéricos de Tailwind en esas dos páginas. Los fondos blancos de algunas superficies en modo claro son intencionales.
- Se revisaron las combinaciones de texto con el criterio WCAG AA de 4.5:1. En modo claro: Azul Noche sobre Crema 14.83:1; Gris Asfalto sobre Crema 5.57:1; Verde Ruta sobre Crema 4.93:1; Crema sobre Verde Ruta 4.93:1; Azul Noche sobre Naranja Pedal 7.20:1. La advertencia usa Azul Noche sobre el amarillo suave compuesto sobre Crema (13.99:1).
- En modo oscuro, Crema sobre Gris Asfalto alcanza 5.57:1 y sobre Azul Noche 14.83:1. Se evita Verde Ruta sobre Azul Noche (3.01:1) y Gris Asfalto sobre Azul Noche (2.66:1) como texto: en las superficies oscuras se usa Crema. La etiqueta superior de la portada también se ajustó a Crema en oscuro para corregir su contraste.
- En DevTools se emuló `prefers-color-scheme: dark` y se verificaron la landing y el kit en ambos temas, incluidos alertas, campos y placeholders. Los campos conservan anillo de foco visible; el CSS generado se recompiló desde la CLI.

### Medición de recursos

La CLI genera `nocturna/src/output.css` con `--minify`: **26.300 bytes (25,68 KiB)** en disco. En DevTools Network, al cargar la portada v2.0 de [Rueda Libre](https://eclipsest.github.io/rueda-libre/), Bootstrap 5.3.8 reportó:

| Recurso Bootstrap | Transferencia (incluye cabeceras) | Cuerpo codificado | Tamaño decodificado |
|---|---:|---:|---:|
| `bootstrap.min.css` | 33.348 B | 33.048 B | 232.111 B |
| `bootstrap.bundle.min.js` | 24.769 B | 24.469 B | 80.496 B |
| **Total** | **58.117 B** | **57.517 B** | **312.607 B** |

El CSS Tailwind se midió como archivo minificado local; la tabla de Bootstrap refleja la transferencia real observada en Network y sus tamaños de respuesta. Por ello, no se toma la diferencia como una comparación idéntica de compresión, pero sí muestra el costo del CSS y JavaScript de Bootstrap juntos frente al CSS generado para esta landing. La medición no incluye imágenes ni Google Fonts.

### Bootstrap vs Tailwind y recomendación

| Criterio | Experiencia con Bootstrap v2.0 | Experiencia con Tailwind en Rueda Nocturna |
|---|---|---|
| Curva de aprendizaje | Sus componentes, grilla y utilidades conocidas permiten montar rápidamente páginas con estructura convencional; hay que aprender sus convenciones y dependencias de componentes interactivos. | El resultado visual se compone utilidad por utilidad y el HTML se vuelve verboso si se repiten listas. La CLI, el tema y dos clases `@apply` resolvieron el flujo de producción y la repetición principal. |
| Personalización | La paleta y componentes se adaptan con CSS/variables del tema, pero la hoja compartida sigue siendo necesaria para la identidad y componentes propios. En la migración de la hoja de distribución se pasó de 697 a 251 líneas (reducción de 64 %). | `@theme` genera utilidades de color y fuente de marca; `@apply` permite encapsular botones sin trasladar el estilo de las cards fuera del kit. `--minify` produjo 26.300 B para esta landing. |
| Tamaño final | En la medición Network, CSS y bundle JavaScript transfirieron 58.117 B en conjunto (57.517 B de cuerpo codificado). | El CSS minificado local ocupa 26.300 B y la landing no necesita un bundle JavaScript de Tailwind. La medición local no incluye la compresión HTTP ni fuentes/imágenes. |
| Casos de uso | Conveniente para mantener el sitio completo, con varias páginas, grillas y componentes interactivos compartidos, y aprovechar el sistema que ya funciona en v2.0. | Conveniente para micrositios o campañas con una identidad visual muy particular, donde interesa generar solo las utilidades usadas y ajustar el diseño con precisión. |

**Recomendación:** mantener Bootstrap para la próxima versión integral de Rueda Libre. Aunque Tailwind dio un CSS minificado menor para esta landing y simplificamos los botones repetidos, la versión completa ya cubre varias páginas con la grilla y componentes Bootstrap, y la migración previa redujo en 64 % el CSS propio de distribución. Cambiar todo el sitio ahora obligaría a reconstruir y mantener esos componentes; Tailwind queda como buena opción para campañas independientes con diseño altamente personalizado.
