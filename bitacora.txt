## Uso de elementos semánticos
Los contenedores `div` que agrupaban la etiqueta y su control fueron reemplazados por `label`, que asocia cada campo con su nombre. El `div` usado como envoltorio del formulario de reservas se reemplazó por una `section` identificada por el título "Reserva tu bicicleta". Los `span` que indicaban que un campo era opcional se reemplazaron por `small`, apropiado para texto secundario.

## Formulario de reserva
El correo usa `type="email"` para validar una dirección con formato de correo; el tipo de bicicleta usa un `select` porque se elige una opción de una lista cerrada; la duración usa botones `radio` porque las opciones son mutuamente excluyentes. La confirmación usa una casilla obligatoria para registrar la aceptación explícita, y los detalles adicionales se recogen con un área de texto para permitir respuestas libres.

| Combinación de colores | Contraste | Clasificación |
| Blanco sobre Verde Ruta | 5,31:1 | Apta para texto normal |
| Blanco sobre Naranja Pedal | 2,22:1 | No apta |
| Azul Noche sobre Naranja Pedal | 7,20:1 | Apta para texto normal |
| Azul Noche sobre Crema | 14,83:1 | Apta para texto normal |
| Gris Asfalto sobre Crema | 5,57:1 | Apta para texto normal |
| Verde Ruta sobre Crema | 4,93:1 | Apta para texto normal |
| Naranja Pedal sobre Crema | 2,06:1 | No apta |
| Blanco sobre Azul Noche | 15,97:1 | Apta para texto normal |

Como resultado, seis combinaciones son aptas para texto normal y dos no cumplen el contraste mínimo. Se recomienda evitar el texto blanco sobre naranja y el texto naranja sobre crema, utilizando Azul Noche como alternativa para mejorar la legibilidad.

## MiniReto de diseño responsive

Se reorganizó `style_prueba.css` con estilos base móviles y media queries `min-width` en 768 px (tablet) y 1200 px (escritorio). Se conservó el viewport existente y se ajustó el diseño de portada, galería de rutas, navegación, pie de página y reservas.

### Problemas encontrados y solución

1. **La navegación se desbordaba en celulares:** los enlaces tenían un ancho fijo y la lista usaba espacios de 150 px. Se cambió el encabezado móvil a columna, con el nombre centrado arriba y los enlaces centrados debajo; desde 768 px vuelve a la fila horizontal.
2. **La portada y las imágenes de rutas no se adaptaban:** la portada y la galería forzaban varias columnas, y algunas imágenes usaban altura de 100 %. Se dejó una columna como base, se agregaron rejillas de dos y tres columnas según el ancho, y se limitaron las imágenes al contenedor con proporción y recorte controlados en las tarjetas.
3. **Las tablas de tarifas ocupaban más que la pantalla:** el relleno era amplio para tablas de cuatro y cinco columnas. Se fijó el ancho al contenedor, se redujeron tipografía y relleno en móvil y se permitió que el texto largo se ajuste dentro de las celdas; en tablet vuelve un tamaño mayor.
4. **El formulario de reservas tenía columnas incompatibles con móvil:** la definición `minmax()` de la rejilla era inválida y el horario estaba anidado en el formulario. Se corrigió la rejilla, se ordenó el marcado y se dejó el horario como columna lateral desde 1200 px, apilado en pantallas menores.

### Verificación responsive

Se comprobó la página de inicio, tarifas y reservas en Chromium con viewports de 360, 768, 1200 y 1280 px. No hubo desbordamiento horizontal; las imágenes y tablas quedaron dentro del ancho visible. La navegación cambió de columna a fila a partir de 768 px, la galería pasó de una a dos y luego tres columnas, y el horario de reservas pasó a columna lateral a partir de 1200 px.

## Comparación de la grilla propia con Bootstrap 5.3

- **Tiempo invertido:** aproximadamente 2 minutos en reconstruir y comprobar la página de prueba.
- **CSS de distribución de la flota en la versión propia:** 11 líneas en `style_prueba.css`: 5 para la grilla base de una columna, 3 para dos columnas desde 48 rem y 3 para tres columnas desde 75 rem.
- **Clases en esta versión Bootstrap:** cada una de las 7 tarjetas usa `col-12 col-sm-6 col-lg-4 col-xl-3` (4 clases por tarjeta; 28 usos en total). El contenedor añade `container`, `row` y el gutter `g-4`. No se añadió CSS propio ni se enlazó `styles.css`.
- **Qué dio Bootstrap sin esfuerzo:** puntos de quiebre estándar para una, dos, tres y cuatro columnas; separación consistente entre tarjetas; contenedor adaptable, estilos de tarjeta, tipografía y espaciado. El CSS y el bundle JavaScript se cargan desde el CDN oficial 5.3.8.
- **Qué control se pierde:** frente a las reglas propias, se reduce el control fino del diseño de tarjetas, colores, tipografía, separación y apariencia de imágenes; para cambiar esos detalles hay que elegir utilidades/componentes de Bootstrap o añadir CSS propio, lo que esta página de prueba evita deliberadamente.
- **Comprobación:** en modo dispositivo se verificaron 375, 576, 991, 992, 1199 y 1200 px; la flota mostró respectivamente 1, 2, 2, 3, 3 y 4 columnas. Las siete imágenes cargaron y no hubo solicitudes fallidas, respuestas HTTP de error ni errores de consola para CSS/JS del CDN.

## Utilidades Bootstrap para beneficios y reservas

Consulté la documentación oficial de Bootstrap 5.3 (utilidades de espaciado, display, flex y colores) para construir la sección de beneficios y la franja de reservas sin CSS propio:

- `col-md-6`: ocupa la mitad de la fila desde el breakpoint `md`; con `col-12`, cada beneficio ocupa todo el ancho en celular.
- `d-none d-md-block`: oculta el elemento decorativo en celular y lo muestra como bloque desde `md`.
- `flex-column flex-md-row`: apila el contenido en celular y lo dispone en fila desde `md`.
- `gap-4`: establece separación uniforme entre elementos del contenedor flex.
- `text-bg-dark`: aplica de forma conjunta fondo oscuro y texto claro, con el contraste definido por Bootstrap.

## Integración de Bootstrap en la página de inicio

Bootstrap 5.3.8 se carga antes de `style_prueba.css`, que es la hoja existente compartida por el sitio (no existe un archivo `styles.css`). La portada, servicios, flota, rutas y beneficios ahora usan `container`, `row`, columnas responsivas, gutters y utilidades. Se retiraron las reglas de distribución propias que Inicio dejó de usar; las reglas de tablas, tarifas y reservas permanecen señaladas en la hoja.

### Conflictos observados en DevTools y solución

1. **Ancho del contenedor:** la antigua regla `main { width; margin; }` ganaba a `.container` y reducía el ancho disponible. Se dejó `main` para el crecimiento flexible y se limitó el ancho propio a `main:not(.container)`, de modo que `.container` de Bootstrap controle Inicio.
2. **Tipografía, márgenes y color de encabezados:** los estilos globales `h1`–`h6` cambiaban el aspecto de los títulos de Bootstrap. Se conservaron Georgia y el azul noche de marca; `fs-*` define los tamaños, `mt-0`/`m-0` controla los márgenes de los encabezados de tarjetas y `.card-title, .card-header` mantiene el color de marca sin `!important`.
3. **Enlaces de Bootstrap frente a la identidad del sitio:** el selector global `a` aplica el verde de marca, texto blanco y estados naranja, en lugar del enlace azul subrayado de Bootstrap. Se mantuvo esa decisión visual en la hoja cargada después del CDN; `.cta-button` conserva explícitamente el estilo de llamada a la acción. DevTools confirmó los colores de marca en los enlaces y los valores responsivos de las utilidades Bootstrap.

**Verificación:** se comprobó Inicio en modo dispositivo a 360, 768 y 1280 px. La grilla muestra una columna en móvil, adapta flota y beneficios a dos columnas desde `sm`/`md`, y alcanza tres/cuatro columnas en escritorio según cada sección. No hubo desbordamiento horizontal ni solicitudes fallidas; las 19 imágenes cargaron y el CDN no reportó respuestas HTTP de error.
